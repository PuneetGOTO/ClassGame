# Campus Quest 校園闖關

50 位玩家、10 支五人隊伍、三至四樓的 20 個固定遊戲房間。每人打 10 款不同遊戲，伺服器配對後抽出房間。大螢幕顯示棋盤、賽道或題目，玩家用手機當手掣。

## 在 Windows 啟動

需要 **Node.js 24.11.1 或更新的 24.x LTS** 及 npm。從本專案根目錄執行下列 PowerShell 指令。

```powershell
npm.cmd ci
npm.cmd run build
if (!(Test-Path .env)) { Copy-Item .env.example .env }
npm.cmd start
```

開啟 [校園地圖](http://localhost:3000/) 或 [管理後台](http://localhost:3000/admin)。首次本機啟動會建立 `data/game.sqlite`，自動建立 10 支空隊伍和 20 個站點。若 `.env` 的金鑰欄位留空，程式會在 `data/local-credentials.json` 產生本機金鑰。使用該檔的 `adminKey` 登入後台。Linux 和 macOS 將指令中的 `npm.cmd` 改為 `npm`。

| 入口 | 用途 |
| --- | --- |
| `/`、`/?floor=4` | 三樓及四樓平面圖，點選房號查看本站遊戲 |
| `/controller` | 學號登入或暱稱登記、配對、報到、觸控手掣與闖關紀錄 |
| `/host?id=HOST-01` | 固定大螢幕的主機登入、入場 QR Code 和分屏對戰 |
| `/leaderboard` | 個人排名與隊伍排名 |
| `/admin` | 學生帳號、站點與隊伍、排行榜管理、場次紀錄及稽核 |
| `/api/health` | 確認中央伺服器可用 |

## 讓手機和大螢幕加入同一個活動

1. 將中央電腦、玩家手機及主機接入彼此可存取的校園網路。用 `ipconfig` 查中央電腦實際的區網 IPv4 位址，並允許活動網路連到伺服器的 TCP 3000。Wi-Fi 若開啟用戶端隔離，需由校園網路管理員提供可連線的活動網段。
2. 在 `.env` 設定 `PUBLIC_URL=http://192.168.1.20:3000`，把範例 IP 換成中央電腦的 IP，然後重新啟動。使用 `BIND_ADDRESS=0.0.0.0` 供區網裝置連接。先在手機瀏覽器開啟相同網址確認網路。
3. 在後台「站點管理」查看每台主機的專屬金鑰。讓固定大螢幕打開 `/host?id=HOST-01` 至 `/host?id=HOST-20`，各自輸入對應金鑰。登記後可以切換全螢幕。
4. 玩家從 `/controller` 輸入學號及登入碼。活動若開放暱稱登記，也可用暱稱加入。登入後按「尋找對手」，配對成功後在兩分鐘內到指定房間。用手機相機掃描大螢幕上的 QR Code，將手機轉成橫向，再按「我已準備好」。每間房的 QR Code 每 30 秒換碼。
5. 場次按各遊戲的最低人數開始。可配成 1 對 1、三人對戰、2 對 2 或四人混戰。3 秒倒數後開打，手機顯示玩家編號、陣營與操作按鍵。電視上的同色區域對應兩位隊友共同操作的棋盤、賽道或題目。
6. 看大螢幕操作。拖曳左側搖桿移動角色或游標，鬆手即停。跳躍、攻擊、選車及確認用右側按鈕。恐龍逃亡用蹲下和跳躍按鈕，選擇題和數字題則用各自的答題按鍵。完成一場後可尋找下一場對戰。

20 款遊戲都用橫向手掣。手機畫面未隨裝置轉動時，請關閉直向鎖定。瀏覽器支援時，可按手掣上的「切換橫向全螢幕」。

史萊姆排球在四樓 414 室（HOST-19），配對 1 對 1 或 2 對 2。所有玩家在同一座球場，用手機左側搖桿拖曳移動，右手可以同時按跳躍擊球。鬆開搖桿便停止移動。球在對方半場落地可得一分，60 秒後由得分較高的一方獲勝，同分為平手。

霓虹氣墊球在三樓 308 室（HOST-07），配對 1 對 1 或 2 對 2。看大螢幕，用手機搖桿移動自己的球拍。先進 5 球便獲勝，60 秒到時以比分決勝，同分為平手。也可在雙人測試房選擇此遊戲。

霓虹炸彈人接替三樓 307 室（HOST-06）的迷宮吃豆。正式賽四人到齊後抽選 2 對 2 或四人混戰，練習房可自行選模式，由兩名 AI 補位。拖曳手機左側搖桿走位，右手同時可按放炸彈。場地在第 35 秒開始縮小。

和風劍道對決接替四樓 411 室（HOST-17）的龍之遠征，支援 1 對 1 或 2 對 2。用左側搖桿左右移動，右手按跳躍或斬擊。擊倒對方全隊即勝，滿 60 秒時比較剩餘血量。替換前的成績會繼續計入排行榜。

三樓與四樓按原平面圖重繪，地圖首頁顯示樓層切換、房間輪廓和活動房號。每層配置 10 個站點。後台可更改房號、樓層與座標，也可為各樓層獨立上傳 PNG、JPEG 或 WebP。上傳上限為 1.5 MB。

## 學生帳號與排行榜管理

- 在「玩家與隊伍」新增學生，或在「批量新增」貼上每行一筆的 `學號,姓名`，也可直接貼上試算表的兩欄。學號保留前導零。新增後複製各人的 8 位數登入碼並交給本人。
- 可按學號、姓名、隊伍或狀態搜尋。編輯既有玩家以綁定學號，原有的隊伍和闖關紀錄會跟隨帳號。登入碼可重發，帳號可停用或重新啟用。學生換手機時以同一組學號和登入碼登入。
- 暱稱登記預設開放。只接受管理員建立的帳號時，在「玩家與隊伍」關閉暱稱登記。學號只顯示在管理後台，公開排行榜和成績 CSV 使用玩家名稱。
- 「排行榜管理」可切換屆別、查閱個人或隊伍排名並匯出 CSV。需要開新一屆時，選擇「重置排行榜」，填寫原因並輸入 `RESET` 確認。系統會封存本屆成績、結束本屆的場次與配對，新一屆的積分和闖關進度從零開始。

## 雙人測試房

用同一台電腦登入管理後台，點「測試遊戲」及「開啟測試大螢幕」。兩支手機分別掃描 P1、P2，便可登入兩個測試帳號。QR Code 每 30 秒換碼。換手機時，在大螢幕按對應席位的「重新配對」，再掃描該席的新 QR Code。任一手機或大螢幕均可從 20 款遊戲選關。兩支手掣連線後，把手機轉橫再開局。結束一局便能換遊戲或重玩，測試結果在測試畫面顯示。

## 場次與正式積分

每人從 0 分開始。配對優先找難度相近的玩家。等待一段時間後可搭配不同關次的玩家，場次採用其中最高的難度，各玩家以自己的關次計算分數。

| 個人關次 | 難度 | 一般勝利 | 一般失敗 | 雙倍勝利 | 雙倍失敗 |
| --- | --- | ---: | ---: | ---: | ---: |
| 1–2 | 入門 | +2 | +1 | +4 | −2 |
| 3–5 | 進階 | +4 | +2 | +8 | −4 |
| 6–8 | 高難 | +6 | +3 | +12 | −6 |
| 9–10 | 決賽 | +8 | +4 | +16 | −8 |

- 配對只會抽出各參賽者尚未完成且大螢幕已上線的遊戲房間，優先選擇較少跨層的安排。完成十款需要至少十個房間有可用的主機。
- 找不到合適對手時，系統可安排手機上已「報名陪打」的玩家，兩人到場掃碼後開局。陪打記 0 分，關次維持原有進度。
- 每場限時 60 秒。率先達成目標的一方勝出。全部參賽方答完題組或時間到時，依目標完成比例判定。交通解困以目標車前進的格數比較逾時進度。比例相同則顯示平手，按失敗分值結算，排行榜另外統計和局。有效操作的正式參賽者累計一關。兩方有效操作後才有正式結算。
- 正式賽與練習房的答題遊戲中，每位玩家送出答案後須等候 2 秒才能再次作答。手機顯示等候時間，隊友和對手各自計時。
- 大螢幕斷線時暫停場景和倒數，30 秒內重連可繼續。等候逾時會取消本局，正式賽的已報到玩家返回配對。正式場次、分屏及計時狀態保存在 SQLite。已操作而結算時離線的玩家按失敗計。
- 雙倍挑戰預設 20% 機率。抽中的場次會在開打後第 6 至 16 秒公布挑戰。提前結算的場次會在結果公布。挑戰者從已操作的在線正式參賽者中抽出。機率可在「規則與稽核」調整。
- 十關基礎分全勝為 50 分、全敗為 25 分。隊伍榜以五位成員個人總分的平均排名。排名同分依完成關數、勝利關數、累計完成時間排序。
- 一個房間同時進行一場。結果在大螢幕停留 5 秒。候場時兩分鐘內到場不足兩人，已報到並在線的玩家會回到配對。
- 管理員可取消進行中的場次。已結算的場次可在「場次紀錄 → 查看結算 → 撤銷成績」填寫原因撤銷。原始紀錄保留，積分及進度會重算，玩家可補打缺少的關次。重設正式比賽會另開新一屆，原有場次留在歷史。

## 開發與驗證

```powershell
npm.cmd run dev
npm.cmd run typecheck
npm.cmd test
npm.cmd run test:load
npm.cmd run build
npm.cmd run test:browser
```

開發 UI 在 `http://localhost:5173`，開發代理將 API 和 WebSocket 轉給 `PORT` 指定的 Node 伺服器。要在開發環境跨裝置測試，可在 `.env` 將 `PUBLIC_URL` 指向中央電腦的 5173 埠。瀏覽器測試需要 Chrome、Edge，或 `npx playwright install chromium` 安裝的 Chromium。以 `CHROME_PATH` 可指定瀏覽器執行檔。並發測試包含真實 60 秒遊戲，耗時約 65 秒。測試使用隔離的資料庫與環回位址。

## 正式部署

1. 執行 `npm ci` 和 `npm run build`。將 `dist/`、`package.json`、`package-lock.json`、各 workspace 的 `package.json`、遊戲源碼及上游授權檔一同保留。可在執行主機上使用 `npm ci --omit=dev` 安裝執行相依。
2. 在環境變數或 `.env` 設定 `NODE_ENV=production`、兩組不同且至少 24 字元的 `ADMIN_KEY` 和 `HOST_SECRET`，並設定 `PUBLIC_URL` 為玩家實際使用的活動入口。下列指令可為兩組金鑰各產生一次隨機值。

   ```powershell
   node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
   ```

3. 在專案根目錄啟動 `npm start`。將 `DB_PATH` 指到可持久化的本機磁碟，並讓單一 Node 程序管理該活動資料庫。以服務管理器設定自動重啟時，工作目錄仍需是專案根目錄。
4. 若使用 HTTPS 入口，可把 Node 綁在 `127.0.0.1:3000`，交由反向代理對外提供 HTTPS。將 `TRUST_PROXY` 設為實際可信代理跳數，並把 `PUBLIC_URL` 設為 HTTPS 網址。Caddy 的單代理配置如下。

   ```caddyfile
   campus.example.edu {
       reverse_proxy 127.0.0.1:3000
   }
   ```

5. 活動結束後匯出成績。實體備份可在伺服器正常停止後複製 `data/game.sqlite`，連同有效的環境設定保存在受控位置。還原時先停止伺服器，再把備份放到 `DB_PATH` 後啟動。
